# 007 — MCP foundation and task capability selection

Status: accepted for 0.5.0, 2026-10-22. See the completed implementation and acceptance record below.

Use official Rust SDK rmcp 3.6.0 (Rust 1.88 minimum), explicitly selecting `ClientLifecycleMode::Auto`. Its default `serve` still uses legacy initialization; Auto probes `server/discover` for the 2026-07-28 stateless generation and falls back through the SDK. Native Rust avoids a packaged Node sidecar and keeps policy in the existing authority process. The existing browser helper is unchanged.

The stock SDK HTTP adapter buffers successful JSON bodies without a host-selected limit. `mcp_http.rs` implements only its transport trait using the existing reqwest version; the SDK owns protocol serialization, negotiation, request metadata and response semantics. Each request rechecks DNS, rejects mixed/private addresses, pins resolution, ignores proxies and blocks redirects. Explicit local mode accepts literal loopback IPs and blocks known administrative ports. HTTPS/443 is mandatory for public endpoints. JSON/SSE bodies have a 1 MiB request-response stream limit and a 16 MiB connection budget. No separate legacy SSE endpoint architecture is added.

`capabilities.rs` builds a shared native/integration metadata catalog and makes deterministic task selections. `agent_mcp.rs` connects selected integrations after review, retains them in the existing Session across model transitions, exposes at most eight MCP schemas totaling 24 KiB, and brokers calls through intent/mode checks and exact argument approval. A compact `mcp_find_tools` index selects eligible connected schemas for the next turn without granting new connections or calls. Browser-only tasks reject custom integrations. Every MCP call is separately reviewed, including read calls that disclose arguments to another service. Connection consent, schema exposure and action consent remain distinct. Native tools also check the selected groups at dispatch.

Unknown tools are conservatively classified as potentially mutating; server annotations do not lower risk. Official presets expose only a local read-tool allowlist. GitHub additionally sends read-only, lockdown and bounded toolset headers to its fixed upstream endpoint. Lockdown is extra filtering, not authority. Context7 exposes its resolver and documentation query tools. Tool identities are server-UUID/name hashes, independent of display names. Tool-list refresh precedes action approval, and changed schemas require a fresh turn.

Settings alone saves server configurations. Stdio requires an installed explicit executable, bounded arguments, working directory and confirmation. `process-wrap` starts it suspended, assigns a Windows Job, then resumes it; kill-on-drop and awaited cleanup control its process tree. Stderr is discarded. Stdout has a 1 MiB frame cap and 16 MiB lifetime cap. This is process supervision, not a sandbox: approved custom programs run as the user.

Credentials are passed separately from configuration, sealed using the existing Windows DPAPI blob store with a random salt, and referenced by opaque encrypted-blob IDs. They are supplied only to the selected transport. Exact credential echoes are removed from observation strings and object keys before serialization; matching discovery entries are withheld. Generic redaction remains best effort. Removing/replacing a configuration does not prune retained encrypted blobs. One credential can be referenced by selected environment/header names; ambient environment credentials are not imported. OAuth, token refresh and elicitation are unsupported; untrusted input flows are refused. Safe status is persisted separately and Settings can cancel discovery or clear the credential reference.

MCP output is bounded untrusted evidence. Its compact record enters Activity, continuation and offline handoff; it cannot grant capabilities or approvals. Connections close before terminal publication. Failed/ambiguous tool calls are not automatically replayed, and HTTP session recovery is disabled. Startup does not connect integrations.

Actual model/service checks, fault regressions and retained limits are explicit in [completed QA](../QA_0.5.0_COMPLETION.md). This decision does not claim exhaustive security testing.
